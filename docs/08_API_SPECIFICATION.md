# 08 API SPECIFICATION - FitWise

Version 1.0 | 2026-10-01 | Depends on: 04, 05, 07
Interactive docs (OpenAPI) are generated by FastAPI at `/docs` and `/openapi.json`. Keep this file and the code in sync; disable `/docs` in production or protect it.

## How the AI agent must use this file
- Implement endpoints exactly as specified: path, method, auth, validation, response, errors.
- Every endpoint needs a Pydantic request and response schema, one valid-input test and at least one invalid-input test, plus a 401 test if it is protected.
- Never trust a user id from the request. Use the session user.

## 1. Conventions
| Item | Rule |
|---|---|
| Base path | `/api` (add `/v1` before any public API release) |
| Format | JSON in and out (`Content-Type: application/json`) |
| Auth | Session cookie `fitwise_session` (HttpOnly, Secure, SameSite=Lax) |
| State-changing requests | POST, PUT, PATCH, DELETE only; require header `X-Requested-With: fitwise` |
| Dates | `YYYY-MM-DD`; timestamps ISO 8601 UTC |
| Units | kg, cm, g, liters |
| Pagination | `?limit=` (default 30, max 100) and `?offset=` |
| Request id | Response header `X-Request-ID` |
| Max body size | 100 KB |

## 2. Standard error envelope
```
{
  "error": {
    "code": "validation_error",
    "message": "Please check the highlighted fields.",
    "fields": [{"field": "age", "message": "Must be between 5 and 100"}],
    "reference": "a1b2c3d4"
  }
}
```
`fields` appears only for validation errors; `reference` only for server errors. Messages never contain stack traces, SQL, file paths or the user's private values.

| Status | Code | When |
|---|---|---|
| 400 | bad_request | Malformed request |
| 401 | unauthorized | Missing or expired session |
| 403 | forbidden | Logged in but not allowed (role, CSRF header, origin) |
| 404 | not_found | Missing resource or resource owned by someone else |
| 409 | conflict | Duplicate (rare; registration uses generic response) |
| 413 | payload_too_large | Body over limit |
| 422 | validation_error | Pydantic validation failed |
| 429 | rate_limited | Too many requests (`Retry-After` header) |
| 500 | server_error | Unexpected failure (with `reference`) |
| 503 | unavailable | Database or dependency down |

## 5. Endpoint details

### POST /api/auth/register
- **Auth:** none. **Authorization:** none.
- **Request:** `{ "name": "Asha", "email": "asha@example.com", "password": "..." }`
- **Validation:** name 1-80 chars (trimmed, no control characters); email valid, max 254, lowercased; password 10-128 chars, not in a common-password list.
- **Response 201:** `{ "message": "Account created" }` and sets the session cookie (new account) .
- **Errors:** 422 validation; 429 rate limit. If the email already exists, return the same success-style response without revealing it (send no cookie) or a generic message; never confirm that the email exists.

### POST /api/auth/login
- **Request:** `{ "email": "...", "password": "..." }`
- **Validation:** both present, lengths limited.
- **Flow:** find user -> verify argon2 (also run a dummy verify when user not found) -> create session -> set cookie -> write audit_log.
- **Response 200:** `{ "user": { "id": 1, "name": "Asha", "role": "user" }, "has_profile": false }`
- **Errors:** 401 `{"error":{"code":"unauthorized","message":"Email or password is incorrect"}}`; 429.

### POST /api/auth/logout
Deletes the session row and clears the cookie. **200** `{ "message": "Logged out" }`. Idempotent.

### GET /api/auth/me
**200** `{ "id": 1, "name": "Asha", "email": "asha@example.com", "role": "user" }`. **401** if no session.

### DELETE /api/account
- **Request:** `{ "password": "...", "confirm": "DELETE" }`
- Deletes user and cascades all data in one transaction; clears cookie; writes audit_log `account_deleted` (no personal data).
- **Response 200** `{ "message": "Account deleted" }`; **403/401** on wrong password.

### PUT /api/profile
- **Request:**
```
{ "date_of_birth": "2005-04-12", "sex": "female", "height_cm": 162, "weight_kg": 58,
  "activity": "light", "goal": "general_fitness", "diet": "vegetarian",
  "restrictions": "no mushrooms", "experience": "beginner" }
```
- **Validation:** date of birth gives age 5-100; height 100-250; weight 20-300; enums fixed; restrictions up to 200 chars.
- **Response 200:** saved profile plus `is_minor`.
- **Errors:** 401, 422.

### GET /api/analysis
- **Response 200:**
```
{ "age": 20, "bmi": 22.1, "bmi_category": "Normal range",
  "bmi_note": "BMI is not a complete measure of health or body composition.",
  "bmr_kcal": 1380, "maintenance_kcal": 1900, "target_kcal": 1900,
  "protein_g": 70, "carbs_g": 245, "fat_g": 53, "fiber_g": 27, "water_l": 2.0,
  "reasons": [{"text": "Protein target 70 g", "reason": "Based on 1.2 g per kg for general fitness."}],
  "is_minor": false }
```
For minors: `bmi_category` is null and the target never includes a deficit.
- **Errors:** 401; 404 `profile_required` if no profile.

### GET /api/foods
Query: `q` (max 40 chars), `diet`, `meal_type`, `limit`, `offset`. **Response 200:** `{ "items": [ {id, name, serving_desc, calories, protein_g, carbs_g, fat_g, fiber_g, category, veg_type, meal_type} ], "total": 19 }`. **Errors:** 422 on unknown enum.

### GET /api/diet-plan
**Response 200:** `{ "targets": {...}, "meals": [ { "meal": "breakfast", "items": [ {"food": "Oats", "amount": "1 bowl", "reason": "Fiber and steady energy for your fat-loss goal"} ], "kcal": 380, "protein_g": 18 } ], "totals": {...}, "disclaimer": "..." }`.

### GET /api/fitness-plan
**Response 200:** `{ "level": "beginner", "week": [ {"day": "Mon", "focus": "Strength", "exercises": [...], "reason": "..."} ], "today": {...} }`.

### GET /api/wellness-score?date=YYYY-MM-DD
**Response 200:** `{ "date": "2026-10-01", "total": 78, "parts": [ {"name": "Nutrition", "score": 25, "max": 30}, ... ], "biggest_improvement": {"name": "Hydration", "reason": "You logged 1.0 L of 2.0 L"}, "notice": "This score is not a medical measurement." }`.

### PUT /api/progress/{date}
**Request:** `{ "weight_kg": 58.2, "exercise_min": 30, "water_l": 1.8, "protein_g": 55, "calories": 1800 }` (all optional, at least one required). Recalculates and stores `wellness_score`. **200** returns the record. **422** on invalid date or out-of-range values.

### GET /api/progress?from=&to=&limit=
Returns only the caller's records ordered by date.

### POST /api/exercise-sessions
**Request:** `{ "exercise": "squat", "reps": 12, "duration_min": 2.5, "date": "2026-10-01" }`. Only counts and time; no media. **201** returns the saved row.

### POST /api/supplements (built)
**Request:** `{ "age": 25, "weight_kg": 70, "diet": "non_vegetarian", "goal": "muscle_gain", "conditions": ["none"], "injury": "none", "on_medication": false }`
**Validation:** age 5-100; weight 15-300; fixed enums.
**Response 200:** `tier` (`standard`, `minor`, `doctor_first`), `headline`, `protein_target_g` (null when gated), `food_first`, `supplements[]` (each with `why`, `what_it_is`, `how_it_works`, `typical_range`, `cautions`, `interactions`, `buy_tips`, `shop_links`), `notes`, `disclaimer`.
Inputs are never stored or logged. Future: prefill from profile in the frontend.

### POST /api/wellness-screening
**Request:** `{ "answers": { "frequent_tiredness": true, "skipping_meals": false, "very_low_activity": true, "poor_sleep": false, "low_diet_variety": true, "recurring_symptoms": false }, "save": false }`
**Response 200:** `{ "result": "moderate_concern", "message": "...", "disclaimer": "This screening is not a medical diagnosis. Consult a qualified healthcare professional for medical concerns." }`. Never names a disease. Saved only when `save` is true.

### GET /api/dashboard
Combines analysis, today's score, today's recommendations (with reasons), today's workout and progress bars so the page needs one call.

### POST /api/chat (optional)
**Request:** `{ "message": "How can I improve protein intake?" }` (max 500 chars). **Response 200:** `{ "reply": "...", "disclaimer": "..." }`. The response never contains diagnosis, doses for gated users, or system details. **503** if the chatbot is disabled.

### GET /api/admin/stats
Admin only: counts of users, active sessions, error rate and request totals. Never returns individual health data.
